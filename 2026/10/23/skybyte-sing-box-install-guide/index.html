sing-box 一键脚本搭建教程：Reality、HY2 与客户端导入

发表于2026-10-23|更新于2026-10-23|技术教程 / 网络链路
|浏览量:
SKYBYTE · SING-BOX · 从安装到实际连接

先搭通一个 Reality 节点，再按需增加 HY2、WARP 和用户管理。

按 SKYBYTE Manager v2.8.6 的实际菜单编写，首次安装使用本版测试的 sing-box 1.14.3。核对日期：2026-10-23。

从 Reality 主线开始 ↓打开安装命令与 VPS 选购页 ↗
第一次搭建，按这条路线走：准备 VPS → 登录 SSH → 运行安装命令 → 选择 1 → 1 → 放行实际 TCP 端口 → 导入客户端 → 做真实连接测试。HY2、BBR、WARP 和配额管理都可以在节点连通后再配置。

本文中的 1 → 1 表示先在主菜单输入 1，再在子菜单输入 1，每次输入后按回车。一次操作结束后通常会回到主菜单，下一项操作重新按完整路径进入。

1. 准备 VPS、系统与端口

准备一台能通过 SSH 登录、能访问软件源与 GitHub 的 Ubuntu/Debian VPS，并保留服务商的网页控制台。本文以新装 Debian 12/13 或 Ubuntu 24.04 为例；脚本依赖 systemd，普通共享虚拟主机和缺少系统服务管理能力的容器不适合直接照做。

需要掌握四项信息：VPS 公网 IP、SSH 端口、root 登录方式、服务商防火墙入口。SSH 端口可能不是 22，以服务商控制台和你自己的设置为准。尚未选购 VPS，可先看四家服务商的选购方向，按预算、线路和 IP 需求选择。

先选一种部署方式

方案安装入口默认公网入站域名与证书适用情况
VLESS + Reality + Vision1 → 1TCP 443无需自购域名或申请自己的 TLS 证书先完成一个直连节点，作为本文主线
Hysteria2（HY2）1 → 2UDP 443需要 TLS；可自签、使用已有证书或托管 ACME客户端和两端网络都支持所需 UDP 通信
Reality + HY2 双协议1 → 3TCP 443 + UDP 443Reality 与 HY2 各按自己的要求配置希望保留两种连接方式用于比较与备用

TCP 443 与 UDP 443 是两种不同的传输协议，双协议可以同时使用数字 443。已有网站占用 TCP 443 时，普通 Reality 安装会报端口占用；改用 1 → 6 → 3 的自定义端口安装入口，或先规划已有服务的端口。

服务商控制台里的安全组/云防火墙与 VPS 内部的 UFW 是两层配置。脚本不会替你修改服务商安全组。 放行 TCP 443 也不会同时放行 UDP 443。

2. 登录 VPS，安装并打开管理脚本

从自己的电脑连接 SSH

下面是连接格式示例。203.0.113.10 是文档示例 IP，请换成你的 VPS 公网 IP，端口也换成实际值。这条命令在自己电脑的终端运行；成功登录后，后续安装命令才在 VPS 上运行。

ssh -p 22 root@203.0.113.10

如果服务商提供的是带 sudo 权限的普通账户，先登录该账户，再执行 sudo -i 切换到 root。可以在 VPS 执行以下只读命令确认环境：

id -u
cat /etc/os-release
uname -m
systemctl --version

id -u 应返回 0；系统应为 Ubuntu/Debian，并能使用 systemd。这里检查的是安装环境，还没有部署节点。

执行一行安装命令

在 VPS 的 Bash 终端运行：

(if ! command -v curl >/dev/null; then apt-get update && apt-get install -y curl ca-certificates; fi && script=$(curl -q -fsSL --max-time 60 https://raw.githubusercontent.com/skylink9119/sing-box-v2/main/bootstrap.sh) && bash -c "$script")

没有 curl 时，这条命令会先安装 curl 与 CA 证书；仍需有可用的 APT 软件源和网络。启动入口会继续检查系统并下载管理脚本。下载失败时先处理显示的错误，再重试，不要把后面的菜单数字粘贴进尚未下载完成的终端。

首次打开选择 1. 简体中文 或 2. English。中文主菜单如下，为 v2.8.6 菜单节选：

1. 节点安装
2. 节点与订阅
3. 服务与日志
4. 服务器与网络
5. 更新与备份
6. 设置与卸载
7. 用户与配额管理
0. 退出

重新登录 SSH 后输入 sb 可打开管理菜单。若当前终端仍缓存旧命令，运行 hash -r 或重新登录；遇到同名入口冲突时，按脚本提示处理，先保留原有自定义命令。

确认规则：看到 [y/N] 时，输入 y 或 Y 才确认；直接回车、n 或 N 都会取消。参数提示里的 [默认值] 则表示可回车采用该参数，两种提示含义不同。

3. 主线：搭建 Reality + Vision 节点

在主菜单选择 1. 节点安装，再选择 1. 安装 Reality + Vision，即 1 → 1。脚本会展示声明，阅读后输入 y 确认安装。

交互项如何填写说明
节点名称前缀例如 洛杉矶，或直接回车默认 SKYBYTE；导出会追加 -Reality，中文名称可用
Reality 握手域名可先回车采用 addons.mozilla.org它是握手目标的域名，不是你的 VPS 地址；在 VPS 所在网络中仍需可达
监听端口普通安装固定使用 TCP 443需要其他端口时，从 1 → 6 → 3 安装，或部署后通过 1 → 5 修改

这一流程会安装依赖、下载经摘要校验的官方 sing-box 核心，生成 UUID、Reality 密钥和 Short ID，检查配置后创建服务。Vision flow 已由脚本设置为 xtls-rprx-vision，无需另外寻找一个“开启 Vision”的选项。字段含义可参考 sing-box 官方 VLESS 文档。

结束时应看到“部署完成；请检查云防火墙”，并显示各客户端的节点信息。默认名称类似 SKYBYTE-Reality。如果出现“发现已有配置，拒绝覆盖”，请先确认是不是已经安装过；已有托管节点应从 1 → 5 修改，不要反复尝试覆盖首次安装。

请记住三类参数的区别：服务器地址是客户端连接的 VPS 公网 IP/域名；SNI是 Reality 握手域名；Reality 公钥用于客户端配置。服务端的私钥留在服务器，不需要导入手机或电脑。

4. 可选：安装 HY2 或双协议

还没有节点时，HY2 单协议选 1 → 2，双协议选 1 → 3。双协议安装会先询问 HY2 的证书方式，再询问 Reality 握手域名。已有 Reality 节点想追加 HY2，走 1 → 5 → 4 添加协议，选择 Hysteria2，保留已有节点和凭据。

HY2 的三种证书方式

选择需要准备客户端要求
1 无域名，自动自签名脚本生成与实际公网 IP 身份匹配的证书必须通过可信通道取得公开证书，并让客户端建立对应信任
2 已有证书证书域名、完整证书链路径、私钥路径域名/IP 身份与证书一致，证书链可信且未过期
3 托管 ACME自有域名和验证条件；按提示输入邮箱、选择验证方式使用签发成功的证书，并配置与证书匹配的 SNI

HY2 使用 UDP/QUIC 并需要 TLS。想采用自有域名与公开 CA 证书，可使用脚本的托管 ACME：HTTP-01 要求域名解析正确、公网 TCP 80 可达且该端口没有被已有网站占用；Cloudflare DNS-01 则按提示提供限定授权范围的 DNS Token。管理入口是 5 → 6，自动续签需要显式开启。参考 sing-box HY2 配置和 Hysteria 官方部署说明；本文使用的是 sing-box 实现，由 SKYBYTE 菜单生成配置。

无域名也需要验证证书。自签名模式的节点链接保持验证开启，复制 URI 本身不会让客户端自动信任证书。若客户端无法正确配置信任，优先使用它支持的受信任 CA 证书方案。

双协议部署完成后应得到 名称-Reality 和 名称-HY2 两个节点。默认分别使用 TCP 443 和 UDP 443，随后到系统与云防火墙逐项确认。

5. 放行系统防火墙与云防火墙

先去服务商控制台检查入站规则，再检查 VPS 内部防火墙。下面按本教程的默认端口列出；若改过端口，表格中的 443 必须换成实际端口。

用途入站协议端口何时需要
SSH 管理TCP你的实际 SSH 端口始终保留可用的管理入口
Reality + VisionTCP443安装 Reality 或双协议
HY2UDP443安装 HY2 或双协议
HTTP-01 证书验证TCP80选择对应 ACME 验证方式时

脚本的 UFW 入口是 4 → 2：1 安装 UFW、2 开启、3 关闭、4 查看状态、5 放行端口、6 删除规则。尚未安装 UFW 时先选 1，输入 y；然后重新进入该菜单选 2，人工核实 SSH 端口后再确认开启。开启时会加入实际托管节点的端口规则。

已经开启 UFW 的服务器，节点安装会尝试添加对应端口规则；仍建议通过状态页面核对。手动补规则时，选 4 → 2 → 5，填写数字端口，再填写 tcp 或 udp。两个协议需要分别操作。4 → 3 可检查规则，但它读不到云安全组。

开启防火墙前保留当前 SSH 会话和网页控制台。已有 Docker、Fail2ban 或其他防火墙的服务器，应结合现有策略检查，不要为了排错直接清空整机规则。脚本的“配置检查通过”说明配置可解析，不能证明公网 TCP/UDP 已连通。

6. 导入手机与电脑客户端

通过 2 → 1 重新查看节点和各客户端格式，2 → 2 刷新本地导出，2 → 4 显示小火箭二维码。客户端需要支持相应协议；是否能导入与所选核心能否运行该协议，是两个检查点。

客户端/用途可使用的导出操作重点
Shadowrocket（小火箭）专用节点链接、shadowrocket-nodes.txt、二维码扫描/复制导入节点；HY2 自签证书还需处理信任
v2rayNv2rayn-nodes.txt 或本地 Base64 订阅从剪贴板/文件导入，再确认内核支持与节点参数
Clash Verge Rev / Mihomoclash-verge.yaml作为完整本地配置导入，在代理组选择节点
OpenClash / 已有 Mihomo 配置mihomo-proxies.yaml这是配置片段，需合并代理和所需证书字段
sing-box 客户端sing-box-client.json完整客户端配置；默认使用首个节点，默认本地混合端口 1080

完整配置与片段不要混用。经典 Clash 内核不具备这里所需的协议支持，应选用兼容的 Mihomo 客户端。以上导出均在 VPS 的 /etc/singbox-v2/ 中；可通过 SSH/SFTP 安全取回。本地 Base64 订阅文件不是一个自动上线的 HTTPS 订阅地址。

第一次导入，可以这样操作

  1. 小火箭：在 VPS 选 2 → 4，用客户端的扫码功能导入二维码，或复制小火箭专用 URI 后使用剪贴板导入。选中新增节点、开启连接，并按系统提示允许建立 VPN 配置，再用浏览器测试。二维码只包含该节点的信息，自签 HY2 还需按下文建立信任。
  2. v2rayN：复制 v2rayn-nodes.txt 中所需的单节点 URI，使用客户端的从剪贴板导入功能，选中节点。确认协议核心支持后启用系统代理或按需求启用 TUN，再测试实际网页访问。
  3. Clash Verge Rev：通过 SFTP 将 clash-verge.yaml 取回电脑，作为本地配置导入并启用，在代理组选择目标节点，再开启需要的系统代理/TUN。不要把完整 YAML 当作单个节点链接粘贴。

各客户端的按钮名称和入口可能随版本变化，上面的步骤强调“导入 → 选中 → 启用接入方式 → 实际请求”这四件事。只在列表里看到节点，流量还不会自动经过它。

Reality 导入后核对这些字段

字段应与什么一致
地址 / 端口VPS 的客户端连接地址与实际 TCP 端口
UUID脚本导出的 UUID
传输与安全TCP、Reality；界面名称随客户端不同
Flowxtls-rprx-vision
SNI、公钥、Short ID以该节点最新导出为准，保留导出的指纹等其他参数

导入后选中该节点，按客户端提供的系统代理或 VPN/TUN 接入方式启动连接，再用浏览器实际访问网页。仅点击“延迟测试”或看到一个毫秒数，还不足以确认所需应用已经通过该节点访问。

HY2 自签名证书如何处理

  1. 从自己的 VPS 经可信 SSH/SFTP 取得 /etc/singbox-v2/hy2-client-ca.pem，并查看 subscription-notes.txt 中的信任说明。
  2. 在 VPS 上运行下面的只读命令核对公开证书指纹，再通过可信通道与导出说明比对。
openssl x509 -in /etc/sing-box/hy2-selfsigned.crt -noout -fingerprint -sha256

sing-box JSON 和 Mihomo 完整 YAML 会内嵌所需公开证书。小火箭/v2rayN 的 URI 导入则取决于其具体实现对 CA、指纹字段的支持；无法确认信任是否生效时，查看客户端 TLS 错误日志，或使用受信任 CA 证书。

iPhone 可使用导出的 hy2-client-ca.mobileconfig（仅 CA 证书生成该文件），按系统提示安装后，在设置 → 通用 → 关于本机 → 证书信任设置手动开启对应根证书的完全信任。安装描述文件与开启信任是两个步骤；具体客户端是否采用系统信任，还需用实际连接验证。只信任你自己取得、核对指纹的证书，停用后可删除。操作路径参见 Apple 官方说明。

不需要传输服务端的 hy2-selfsigned.key、Reality 私钥或服务器配置。分享节点时只发送相应客户端导出。

7. 分三层确认节点真正可用

第一层：VPS 服务与配置

从 3 → 1 选择状态或配置检查；也可以在 VPS 运行：

systemctl is-active sing-box
systemctl is-enabled sing-box
/usr/local/bin/sing-box check -c /etc/sing-box/config.json

默认安装成功后，前两项应分别显示 active 和 enabled，配置检查应成功退出。它们说明本机服务和配置情况。

第二层：实际监听与两层防火墙

按所安装的协议检查。以下为默认端口，只安装 Reality 时没有 UDP 监听是正常情况，反之亦然：

ss -lntp 'sport = :443'
ss -lnup 'sport = :443'

然后核对 UFW/其他系统防火墙和服务商安全组都允许对应协议。UDP 显示监听，仍需客户端从外部发起连接，才能验证实际路径。

第三层：客户端实际请求

启动客户端并选中节点，用浏览器访问常用网页，观察客户端日志。若使用本教程导出的 sing-box 完整客户端配置，且客户端已在本机监听默认 1080 端口，也可在客户端电脑运行：

curl --proxy socks5h://127.0.0.1:1080 https://www.cloudflare.com/cdn-cgi/trace

这条请求会通过指定本地代理，并由代理处理目标域名。ip= 可帮助观察实际出口；未设置额外中转/WARP 时，通常对应 VPS 出口。若你的客户端端口不同，改成它的实际代理端口。手机无需运行这条命令，用浏览器与客户端连接日志验证即可。

配置、监听、公网连通与特定平台可用性是不同层次。完成前面的验证后，再判断视频播放、账号地区和 AI 服务是否满足需求。

8. 可选优化：BBR 与 WARP

BBR + FQ：先确认内核支持

入口 4 → 4。脚本确认后尝试加载 BBR，检查内核可用算法，再设置 TCP 拥塞控制和 FQ 队列。它调整的是系统 TCP 参数，不代表 HY2 的 QUIC 拥塞控制也被切换，更不代表所有链路都会提速。

可在 VPS 查看实际结果：

sysctl net.ipv4.tcp_congestion_control net.core.default_qdisc

成功应用本项设置后应分别为 bbr 和 fq。提示内核不支持时，先保留原系统，不必为完成基础节点搭建而继续强行修改。

WARP：先验证出口，再选择平台

入口 4 → 9，按 v2.8.6 分组：

选项用途
1 / 2 / 3安装官方本机代理 / 使用已有本机代理 / 导入 WireGuard 配置
4选择 Netflix、Disney+、ChatGPT、Gemini、组合或自定义域名后缀
5 / 6切换出站模式 / 管理分流规则
7 / 8验证双栈出口 / 比较直连与 WARP 平台响应
  1. 没有部署 WARP 时按需要选择 1，阅读并确认 Cloudflare 条款；已有可用回环代理则选择 2。默认 SOCKS5 地址为 127.0.0.1:40000，不需要把它开放到公网。
  2. 选择 4，选需要的平台，填写实际代理端口。脚本会检查回环监听与 WARP 出口；验证通过后，再输入 y 应用分流。
  3. 通过 8 比较平台响应，再回到客户端验证实际应用。需要改为直连时，从 5 选择“全局直连”。

“全局 WARP”指本工具托管节点的流量，不改 VPS 操作系统的默认路由。指定域名模式依赖域名匹配与嗅探，IP 直连、ECH 和未覆盖域名可能不匹配。WARP 不保证某个国家或平台解锁，匿名网页检测也不等于账号登录、API 调用或实际播放成功。先搭通基础节点，再逐项开启这些可选功能，更容易判断问题来自哪里。

9. 多人使用：独立账户、配额与订阅

需要把节点交给其他人时，进入主菜单 7。先选 1 初始化用户管理，再选 2 添加用户，填写用户名、上传与下载合计额度（GiB）和有效天数；选 9 查看该用户的节点与二维码。该功能需要先有 Reality/HY2 直连节点，独立 Argo 部署暂不支持受限账户。

每个受限账户有自己的凭据、进程与端口。请把该用户的个人导出发给对方，不要分发管理员节点；管理员节点不受这些用户配额限制。云安全组还需放行个人节点实际分配的 TCP/UDP 端口，不能只留下管理员的 443。

用户菜单用途与注意点
3 / 4查看用量 / 修改额度；修改额度保留原有效期与累计用量
5 / 6启用或禁用 / 删除账户
7 / 13单独重置流量 / 修改从当前时间起的有效天数
14 / 15用户故障诊断 / 进程与资源占用
16签发、重置或撤销个人 HTTPS 订阅 Token

额度没有自动月度重置周期，续期也不会自动清空累计用量。人数上限统计的是未删除账户数量，不能识别真实使用人数。配额通过周期采样执行，适合日常额度管理；每个账户额外消耗内存、CPU 和端口，容量可通过 4 → 7 查看。

如果需要在线订阅，先通过 5 → 6 准备受信任证书，再进入 2 → 6 配置 HTTPS 服务，使用用户菜单 16 管理个人链接，并放行实际 HTTPS 服务端口。订阅 URL 中的 Token 可以取得个人节点凭据，应私密保存；撤销订阅 Token 不会同时轮换已经泄露的节点密码。

10. 修改、更新、备份与卸载

要做什么菜单路径实际影响
重新查看节点 / 二维码2 → 1 / 2 → 4取最新导出，便于重新导入
修改节点名称2 → 3改客户端显示名称，保留 UUID/密码
改端口 / 连接地址 / SNI1 → 5 的 1 / 2 / 3更新后重新导入，核对实际端口规则
添加 / 移除协议1 → 5 的 4 / 5已有部署使用这个入口，保留仍在使用的凭据与用量
服务状态 / 重启 / 配置检查3 → 1子菜单 1 / 3 / 6
查看日志3 → 2显示近期 sing-box 日志
更新管理脚本5 → 4检查正式发布版本，确认后更新管理菜单与脚本功能
更新 sing-box 核心5 → 1选择本版测试核心、最新稳定版或指定版本，先做配置检查
备份 / 恢复 / 管理备份5 → 2 / 5 → 3 / 5 → 7备份含配置、证书、凭据等私密数据，离机副本也需保护
卸载6 → 3卸载前自动备份；保留的防火墙规则、BBR 参数等需另行管理

重要修改前先备份。更新管理脚本与更新协议核心是两件事；更新可能短暂重启此前运行的相关服务，选择合适的操作时间。脚本不做每周自动升级。

如果启用了 HY2 端口跳跃，节点参数修改后原跳跃会关闭，需要按当前端口重新开启。刚入门时先使用一个明确的 UDP 端口完成验证，再从 4 → 5 配置跳跃范围，并同步放行云防火墙范围。

恢复会协调配置与服务，并保留当前仍存在用户的最新策略/累计用量。卸载保留备份、UFW 放行规则、BBR/FQ 设置等系统项，不能将其视为整台 VPS 恢复出厂。

11. 常见问题：按错误发生的位置排查

现象先检查什么下一步
curl: command not found是否使用本文完整的一行入口；APT 源是否能访问完整入口会尝试安装 curl；安装失败先修复软件源或网络，再重试
“发现已有配置，拒绝覆盖”已有 sing-box 配置、二进制、服务或旧面板本工具托管部署走 1 → 5；其他部署先备份并规划迁移
TCP/UDP 443 被占用用 ss 查看对应协议的监听进程从 1 → 6 → 3 自定义端口安装；不要直接终止未知服务
服务未启动3 → 1 的配置检查、3 → 2 日志先修复具体配置、证书或端口错误，再重启
服务 active，但客户端超时客户端地址/端口、实际监听、系统防火墙与云安全组Reality 核对 TCP，HY2 核对 UDP；NAT 还需核对公网映射
Reality 握手失败UUID、Vision flow、SNI、公钥、Short ID 是否来自同一份最新导出重新导入；核对 VPS 到握手目标的网络与服务器时间
HY2 证书错误证书是否过期、SNI/IP 是否匹配、自签证书是否受信任按本教程处理信任，或使用客户端支持的可信 CA 证书
Reality 能用，HY2 不通UDP 规则、客户端核心支持、手机/本地网络是否允许所需 UDP换可用网络做对比，结合两端日志定位；TCP 可用不能证明 UDP 可用
更新后仍看到旧菜单是否更新了管理脚本，而不是只更新核心；是否仍运行旧副本结束旧会话后重新输入 sb，核对顶部脚本版本
WARP 显示在线，平台仍不可用实际出口、平台域名匹配、地区/账号/播放或 API 限制对比直连与 WARP，并在客户端实际验证，不把 trace 结果当作解锁证明

需要进一步查看主服务日志时，在 VPS 执行：

journalctl -u sing-box -n 80 --no-pager

求助时提供系统版本、管理脚本版本、协议、实际端口和脱敏错误。不要公开节点链接、订阅 Token、UUID/密码、服务端配置或私钥。

12. 进阶入口、文件位置与参考资料

基础节点可用后，再按需求使用以下功能：

  • Argo：1 → 4 管理附加隧道，1 → 6 提供独立 Argo、IPv6/NAT 等受限网络入口。Quick Tunnel 用于临时测试，地址可能变化；固定隧道需要事先在 Cloudflare 配置公开主机名与路由。这里的 Argo 节点是独立 VLESS + WebSocket，不承载 HY2/QUIC。
  • IPv6 / NAT：安装时区分本机监听地址、客户端使用的公网地址与服务商映射端口。纯 IPv6 VPS 仍需能下载软件，客户端所在网络也需能到达该 IPv6 地址；只修改导出地址不能自动创建公网映射。
  • 住宅落地中转：4 → 10，子菜单 6 有具体使用说明。需要一台可用的入口与一台可用的落地，目标站点看到的是落地出口；与 WARP 为替代出站策略，启用前先测两段链路。
  • HAProxy TCP 透传：4 → 11，子菜单 12 有说明。用于 TCP 转发；客户端保留落地节点的认证、SNI 和 TLS 信任，连接地址/端口改为入口。它不转发 HY2 的原生 UDP。
位置作用
/etc/sing-box/config.json管理员服务端配置，包含私密参数
/etc/singbox-v2/状态、客户端导出、语言与可选功能配置
/etc/singbox-v2/backups/配置备份，包含凭据与证书等内容
/etc/singbox-v2/users/个人用户的配置、导出与故障信息
/usr/local/bin/sing-box协议核心程序
sing-box.service管理员直连节点的 systemd 服务

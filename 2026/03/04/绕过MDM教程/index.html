macOS MDM 远程管理：先判断，再处理

更新：2026 年 11 月 6 日。重装 Mac 后出现 Remote Management，先确认屏幕显示的组织、设备来源和管理方式。本文整理官方解除路径、恢复模式准备、原教程使用的第三方脚本及排错方法；脚本仅完成源码核对，未在各型号、各 macOS 版本上逐一实测，不承诺通用或永久生效。

仅在你拥有并获准调整管理状态的设备上操作。公司、学校在用设备请联系管理员；二手设备请先让卖家完成组织释放与交接。修改前备份数据，恢复模式下的磁盘操作可能影响账户和文件。

1. 先区分远程管理、激活锁与磁盘密码

看到的提示优先处理方式
Remote Management，显示公司或学校名称向该组织或卖家核实自动设备注册状态，要求完成管理解除与设备交接。
要求原 Apple 账户激活这是激活锁问题，需由原账户持有人或具备相应权限的组织处理，不能套用本文的本地脚本。
磁盘被锁定、要求用户密码或恢复密钥先解锁磁盘；不要把 FileVault 密码、固件密码与 MDM 当成同一种问题。

激活锁与设备管理有不同的处理机制，参见 Apple：Apple 设备上的激活锁。仅仅能够进入桌面，也不能证明设备已从原组织释放。

2. 能联系原组织时，先走官方解除流程

  1. 记录设备序列号与屏幕上的组织名称，通过私下渠道联系卖家或管理员。
  2. 请组织核查 MDM 和 Apple Business／Apple School Manager 中的设备记录，完成对应的退役、解除管理与组织释放。只删除一个本地账户不等于完成交接。
  3. 如涉及激活锁，应先由有权限的人员处理，再释放设备。
  4. 获得释放确认并备份数据后，再按管理员与 Apple 的指引抹掉、恢复设备，联网完成设置并核对结果。

Apple 的设备释放说明要求由具备权限的人员操作，并指出释放后需要抹掉和恢复设备。参见 Apple Business：释放设备。

如果已经能进入桌面，可在系统设置 → 通用 → 设备管理查看描述文件。能否移除取决于管理方式；没有移除权限时应联系管理员。参见 Apple：更改设备管理设置。

3. 恢复模式准备：先确认目标磁盘

  • Apple 芯片 Mac：完全关机后按住电源按钮，出现启动选项后选择“选项 → 继续”。
  • Intel Mac：开机或重启时立即按住 Command（⌘）+ R。
  • 按提示选择管理员并解锁磁盘；下载文件需要可用网络。在顶部菜单选择“实用工具 → 终端”。

参见 Apple：从 macOS 恢复功能启动。进入恢复模式的方法与第三方脚本能否在该系统运行是两回事。

可先执行以下只读命令，记录系统卷与数据卷，确认不是外接备份盘。卷名不一定是 Macintosh HD。

diskutil list
ls /Volumes

磁盘未挂载或加密未解锁时，先在磁盘工具中核对目标卷；不要靠反复重命名、抹盘或删除目录来尝试消除报错。

4. 原教程的第三方脚本：固定版本并分步检查

原教程引用的是 assafdori/bypass-mdm，不是 Apple 官方工具。本次核对固定提交 60583be37d41f314cb04a99e260071fc31a2eaf4 中的 bypass-mdm-v2.sh，避免直接执行随时变化的 main 分支。

源码会尝试识别卷、创建本地管理员、修改 hosts 与本地设置标记，并可能把数据卷改名为 Data。它不会替原组织完成服务器端的设备释放。运行前应查看完整源码，确认目标卷、已有账户与备份；多系统、多数据卷或已有重要数据的环境不宜照搬。

第一步：只下载，不执行。

curl -fL --proto '=https' --connect-timeout 15 --max-time 120 \
  'https://raw.githubusercontent.com/assafdori/bypass-mdm/60583be37d41f314cb04a99e260071fc31a2eaf4/bypass-mdm-v2.sh' \
  -o bypass-mdm.sh

第二步：核对文件。以下摘要仅对应上述固定版本。必须看到校验通过；如果缺少 shasum、下载失败或摘要不符，先停止，不要继续执行。

printf '%s  %s\n' \
  '1aa477aad2ee4b2dbf2e59214dee05b73c81b392d74f89ac341db77597a98256' \
  'bypass-mdm.sh' | shasum -a 256 -c -

摘要一致仅证明文件与本次核对版本一致，不代表兼容性或执行安全保证。阅读源码后，才决定是否继续：

cat bypass-mdm.sh

第三步：仅在授权、备份和源码核对都完成后运行。

bash bypass-mdm.sh

该固定版本的选项 1 为 Bypass MDM from Recovery。以实际显示的系统卷、数据卷和提示为准；信息不符就取消。临时管理员应使用不与已有账户冲突的用户名和独立强密码，不使用旧文推荐的 1234。脚本可能显示输入的密码，不要公开完整终端截图。

脚本打印成功不代表每一步都成功。保留并核对 warning／error；无法判断时停止，把报错行、macOS 版本和磁盘布局整理给可信的技术人员，隐去密码、序列号和个人信息。

5. 重启后核对与账户整理

  • 确认预期账户可以登录，并核查“系统设置 → 通用 → 设备管理”中的实际状态。
  • 确认个人管理员能正常登录、数据可访问，且 FileVault 解锁与恢复方式可用，再决定是否删除临时账户。不要先删掉唯一可用的管理员。
  • 如果再次出现注册界面，回到原组织核实设备释放状态，不能把本地脚本的成功提示当成永久解除证明。

Apple 说明，macOS 14 或更高版本上，仍登记在组织且初次设置时未注册管理的 Mac 可能显示全屏注册体验。因此旧文“一次运行即可彻底解决”的表述不适合作为保证。参见 Apple：自动设备注册与设备管理。

6. 常见报错如何处理

现象检查方向
Could not resolve host检查恢复模式网络与 DNS，确认能访问下载地址。不要通过关闭 HTTPS 证书验证来解决。
curl 返回错误、下载到网页或校验失败停止执行，检查网络和固定链接，重新下载后再校验；不要运行空文件或 HTML 页面。
Could not detect system/data volume检查是否在恢复模式、系统是否已安装、正确卷是否解锁挂载；多卷环境需人工核对。
Read-only file system / Permission denied记录具体路径并核对卷与权限；仅看到“只读”不足以判断应采取何种修改。
用户名已存在或账户创建失败不要覆盖已有账户；先检查目标数据卷与冲突账户。
联网、更新或重装后又提示管理核对组织登记状态与完整日志，不再沿用“补一行 hosts 就能永久解决”的结论。

7. 二手 Mac 交接检查

要求卖家确认组织释放和激活锁状态，保留购买与交接凭证，联网完成设置后再验收。能进入桌面、没有立即弹窗或卖家演示脚本成功，都不能单独替代这一步。具体兼容性必须按实际机型与 macOS 版本验证；本文没有覆盖所有 Apple 芯片与 Intel Mac 的实测矩阵。

📖 前言

越来越多用户开始从 3X-UI、宝塔等面板迁移到 sing-box。相比面板方案，纯 sing-box 配置更透明、资源占用更低，也方便理解协议参数和后续扩展。

本教程适合：

  • 第一次购买 VPS 的新手
  • 不熟悉 Linux 命令的用户
  • 希望摆脱面板依赖、直接管理配置文件的用户

最终结构如下：

这套方案具有以下特点：

  • 不需要购买域名
  • 不需要申请 TLS 证书
  • 不需要安装 Nginx
  • 使用 Reality 模拟正常 TLS 握手特征

本文默认使用 root 用户，因此命令中不添加 sudo。Reality 私钥只能保存在服务端，不能截图、公开或填写到客户端。

🛠️ 十五、常见问题

1. Reality authentication failed

优先检查：

  • 客户端 UUID 是否与服务端一致
  • 客户端是否填写 PublicKey，而不是 PrivateKey
  • PublicKey 是否对应服务端当前 PrivateKey
  • 客户端 Short ID 是否与服务端数组中的某一项一致
  • 客户端 SNI 是否为 www.microsoft.com
  • 客户端连接的 IP 和端口是否属于这台 VPS

如果密钥、UUID 或配置截图曾经公开，请重新生成，不要继续使用泄露的凭证。

2. VPS 时间不正确

📊 十六、为什么选择 sing-box + Reality + Vision？

项目 面板方案 sing-box 纯配置
资源占用 通常较高 较低
配置透明度 依赖面板界面 直接查看配置文件
维护方式 依赖面板版本 使用官方程序和 systemd
扩展能力 受面板功能限制 可按官方配置扩展
学习成本 较低 初次配置稍高

这套方案适合希望长期维护 VPS，并愿意理解服务端配置的用户。对只想快速创建节点的用户，面板方案仍然更直观，应根据自己的需求选择。
